# Repair interactive live-check approval

Kiln's guided setup asks the operator to approve a live model diagnostic. In
interactive mode, entering an affirmative answer is currently treated as a
decline: the diagnostic is not run and setup remains partial. The equivalent
non-interactive approval flag works.

Correct the interactive path so an affirmative answer authorizes exactly one
live diagnostic and a passing result can continue setup to ready. Keep the
authorization boundary strict: denial, cancellation, blank input, and invalid
text must never send the diagnostic request. The semantic decision must remain
identifiable as a live-model-check decision, and changing user-visible prompt
wording must not silently change the input or consent type.

Preserve the documented behavior of the existing non-interactive approve and
deny flags. Add focused regression coverage for the interactive renderer and
the setup path without contacting a real provider or using real credentials.
