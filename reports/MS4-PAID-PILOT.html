Implementation change log

  1. RHEL containerization: replaced the Ubuntu userland with a pinned RHEL 10.2 UBI image while accurately retaining the provider-managed Ubuntu host-kernel disclosure.
  2. Model loading: selected explicit safetensors prefetch for the FUSE-backed volume, cutting pathological startup behavior and making all three pinned checkpoints reproducible.
  3. Service lifecycle: moved vLLM servers into distinct process groups so restart and teardown remove engine descendants and release VRAM deterministically.
  4. Network boundary: replaced unavailable container namespace isolation with an inherited syscall filter that admits AF_UNIX only, plus per-model relays and Unix permissions.
  5. Pi compatibility: routed both bundled and unbundled OpenAI SDK paths through the constrained fetch shim, then proved real completions under the filter.
  6. Preflight: added positive Pi completion checks and negative probes for host TCP, external IPv4, non-Unix sockets, sibling model sockets, and SSH key access.
  7. Result integrity: used fresh source copies, dependency snapshots, per-run users, atomic candidate capture, exact-matrix validation, and stale-marker removal.

Technical interpretation and next strategy

Success rate is the primary outcome; throughput, tokens, and GPU metrics are diagnostics. This pilot should guide the next controlled cycle, not establish a model ranking.

  1. Repeat each task at least three times and add unpublished tasks to reduce run variance and public-history contamination.
  2. Profile Qwen MTP-3 against a no-MTP control because the deployed backend reported a fallback in fused multi-step draft decoding; retain the faster setting only if end-to-end validated success per GPU-hour improves.
  3. Use the utilization and power traces to tune batching only after correctness is stable; the current one-agent-per-GPU topology intentionally favors comparability over saturation.
  4. Upstream or package the Pi Unix-transport hook so the isolation boundary does not depend on patching installed bundles.
  5. Promote only changes that reproduce on the bare-metal RHEL target using the same image digest, model revisions, service flags, and acceptance suite.

Limits: one attempt per model/task, public-task contamination cannot be excluded, and RHEL describes the container userland rather than the provider-managed host kernel.
